# Upgrading

This guide covers upgrades for all supported deployment paths.

## Upgrade Principles (All Paths)

- Use immutable image tags.
- Back up database and storage before upgrading.
- Upgrade `web` and `worker` to the same image tag.
- Migrations run from the `web` role only.

## 1. Pre-Upgrade Backup

### Database

```bash
PGPASSWORD=$DB_PASSWORD pg_dump \
  -h $DB_HOST \
  -U $DB_USERNAME \
  -Fc strata_production \
  > backup-$(date +%Y%m%d-%H%M%S).dump
```

### Storage (Local Backend)

```bash
docker compose cp web:/rails/storage ./storage-backup-$(date +%Y%m%d)
```

If you use object storage (`STORAGE_BACKEND=amazon|google|microsoft`), use your provider backup/versioning controls.

## 2. Upgrade by Deployment Path

### Quick Install / Single-Host Docker Compose

```bash
cd /path/to/strata
curl -fsSL https://strata.do/server/install.sh | bash
```

The installer preserves `.env`, updates compose config, pulls the selected image tag, and restarts services.

### Manual Host Deployment (VM / On-Prem)

1. Set target image tag in `.env`:

```bash
STRATA_VERSION=1.0.0
```

2. Pull and restart:

```bash
docker compose pull
docker compose up -d
```

3. Verify:

```bash
docker compose logs -f web worker
curl http://localhost:3000/up
```

### AWS ECS Manual Deployment

1. Select target Strata image tag.
2. Create new task definition revisions for both services:
- `web` service (with `STRATA_PROCESS_TYPE=web`)
- `worker` service (with `STRATA_PROCESS_TYPE=worker`)
3. Update ECS services to the new task definition revisions.
4. Verify ALB `/up` and worker logs in CloudWatch.

## 3. Rollback

### Docker Compose (Quick Install / Manual Host)

1. Set previous `STRATA_VERSION` in `.env`.
2. Restart:

```bash
docker compose pull
docker compose up -d
```

3. If required, restore database and storage backups.

### AWS ECS

1. Revert `web` and `worker` services to previous task definition revisions.
2. Verify ALB `/up` and worker logs.
3. If required, restore database and storage backups.

## 4. Multi-Node and HA Notes

- Upgrade in rolling order, keeping at least one healthy `web` instance when possible.
- Keep `STRATA_SECRET_KEY_BASE` and all Strata encryption keys identical across all nodes.
- Ensure only one migration writer at a time (via normal `web` rollout sequencing).
